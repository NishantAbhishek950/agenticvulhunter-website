Why AgenticVulHunter

Secure code review, your model, your environment.

Vulnerabilities are not always isolated to one line of code. AgenticVulHunter analyzes repository-level context and can run with local models or supported API providers, depending on your setup.

  • Vulnerable logic can span multiple files and functions.
  • Source code may be sensitive and unsuitable for external model providers.
  • Too much repository context can introduce noise.
  • Large amounts of security knowledge can distract the model from the relevant CWE.
How AgenticVulHunter responds

Focused evidence, adaptive security knowledge, then validation.

Local when you need it

Keep model choice and code location under your control.

Run with a locally deployed open-source model or point the tool at a supported hosted endpoint.

Bring your own model

Your code review should not depend on one AI vendor.

AgenticVulHunter keeps model configuration in the project. Point it at a supported API, select the model ID, and keep the rest of the review workflow the same.

01

Switch models without rewriting the pipeline. Change the provider, endpoint, or model ID in TOML.

02

Use local or hosted endpoints. OpenAI-compatible servers work with the same adapter shape.

03

Keep secrets out of config when needed. API keys can be supplied through environment variables.

.agenticbughunter.toml 
[llm]
provider = "openai"
base_url = "http://localhost:11435/v1"
model = "qwen3-coder:30b"
api_key = "ollama"

[pipeline]
confidence_threshold = 0.75
max_candidates = 5

How it works

Five stages. One supported finding.

Each stage has a clear job, so review stays understandable instead of becoming one giant prompt.

01

Localize

Find suspicious changed lines in the Git diff.

02

Enrich

Gather bounded repository context and relevant symbols.

03

Hypothesize

Retrieve CWE knowledge and form candidate hypotheses.

04

Validate

Judge candidate–CWE pairs against security evidence.

05

Filter

Apply the threshold and emit supported comments.

Quick start

From install to first review.

Install once with pipx, then initialize AgenticVulHunter inside the Git repository you want to review.

01

Install

pipx install "git+https://github.com/awsm-research/AgenticBugHunter.git"
02

Set up your repository

agenticbughunter init --no-hook

--no-hook sets up the project without changing your normal git push workflow.

03

Check your model

agenticbughunter doctor --check-llm
04

Review

agenticbughunter review --base HEAD~1 --head HEAD
